WEATHER WHERE IT MATTERS, 2025

Industry Problem: The absence of site-specific weather data in building energy modelling can lead to prediction errors of up to ±40%, revealing a key limitation in current simulation workflows.

Standard simulations rely on generalised weather files that overlook urban heat island effects and local variability. This project develops a physics-informed prediction framework combining the SUEWS urban climate model with regression machine learning to estimate hourly temperature and humidity at unmeasured locations. The system learns from surrounding weather stations and urban surface characteristics to generate validated, site-specific climate data, delivered through an interactive web tool for architecture and engineering workflows.

Awards

  • Computational Design Award 2025 UNSW Built Environment Graduation Exhibition
  • Graduation Project Featured on Dezeen International architecture & design publication
  • Project was created with industry collaboration Arup: Haico Schepers

Workflow: Meteorological and GIS data from multiple weather stations were processed and used to run the Surface Urban Energy and Water Balance Scheme (SUEWS) model, generating physics-informed urban climate outputs. These outputs were combined with historical weather data to build a machine learning dataset. Several regression models were tested using Leave-One-Station-Out validation to evaluate prediction accuracy for unseen locations. The workflow was then deployed as an interactive web interface allowing users to select sites, view prediction results, and download climate data.

URBAN LENS, 2025

UrbanLens is an AI-assisted planning analysis tool that evaluates uploaded building models against suburb specific LGA zoning and parcel datasets to identify compliance issues and assess site suitability.

Workflow: A Flask web interface processes STL uploads, extracts geometry using Three.js, and combines this data with local zoning datasets. Structured prompts are then sent through an AI API to generate planning insights displayed within the interface.

The LLM does not read raw design files independently. Python backend workflows first process uploaded STL models, reference images, user parameters, and LGA zoning datasets into structured architectural context. That processed data is then embedded into a carefully engineered prompt and sent through the OpenAI API, allowing the model to return planning feedback in four categories: contextual compatibility, environmental/material analysis, zoning compliance, and alternative location suggestions.

ROBOTIC COMPUTING, 2024

Robotic Computing explored custom G-code generation for FDM 3D printing through Python and Grasshopper. Working incrementally from failed prints to refined parametric geometries, the project developed two prototype families; an organic multi-brep form and a lofted elliptical vessel. Each tested across multiple variables including feed rate, extrusion rate, layer height, spike amplitude, and curvature. The course culminated in a group large-scale façade panel fabricated on a KR70 industrial robot using 100% recycled plastic.

For Assignment 2, our group investigated light filtration as a façade design domain. By deliberately scripting controlled overhangs into the toolpath, the printed panel produced shifting shadow geometries when intersected with light — making light itself part of the architectural output. Fabricated on a KR70 industrial robot using 100% recycled plastic.

PIC TO PROJECT, 2024

A Flask-based web tool that uses Roboflow's instance segmentation to analyse uploaded or live-captured photos of buildings, returning estimated percentage coverage of five structural materials [concrete, brick, wood, glass, and vegetation]. The model was trained iteratively across multiple versions, refining image quality, annotation consistency, and dataset size to achieve a final mAP of 98.2% and precision of 97.4%. The system outputs a downloadable annotated image and material data report, designed for early on design decisions; cost estimation, sustainability reporting, and material inventory management within the AEC industry, aligning with UN SDG Goals 9 and 11.

Iterative testing with YOLOv11 instance segmentation model revealed that annotation quality outweighed dataset size, the final model reached 98.2% mAP. Each trained model generates a unique ID plugged directly into the Flask backend, which calls the Roboflow API to run inference and return material detections and space coverage percentages.

URBAN ENVELOPES, 2024

Select any Sydney block on the web interface and real OpenStreetMap road and land data is pulled live into Grasshopper, generating parametric building envelopes, population density analysis, transport routes, and green space distribution on actual Sydney geography. Parameters updated on the website feed back into Grasshopper and update the Three.js viewer in real time.

Population Density Analysis: Highway boundary geometry from OpenStreetMap is populated with points in Grasshopper, then a closest point component calculates proximity to the most user-heavy building centres to simulate where population movement concentrates. The seed point controlled on the website simultaneously drives building inclination and population density; so taller or denser building clusters attract higher population, gradually dispersing toward smaller blocks. This analysis directly informed where rooftop greenery and amenity buildings were placed, prioritising less populated zones for green space.

KARAMBA WITH GRID SHELLS, 2024

Workflow: A catenary surface was generated using Kangaroo physics simulation to form the initial shell geometry. The structure was then converted into a geodesic grid suitable for fabrication and analysed using Karamba3D to test load behaviour and optimise member dimensions. Finally, the design was fabricated through laser-cut components and physically assembled.

The line beams for this model is different to the line beams shown in the form finding model as these line are geodesic curves not polylines, and can be rolled out into straight beams, which is a critical feature needed for fabrication. So this wireframe model is essentially what the final structural model should look like.

For the loads I tested various conditions

  • Gravity: component [The structures own weight]
  • Snow: 1–1.5 kN/m²
  • Wind: 0.84 kN/m²

Combinations of load conditions:

  • Gravity; Gravity + Snow
  • Gravity + Wind
  • Gravity + Snow + Wind

After applying each load condition: Whichever one outputs the largest cross-sectional value with 80% utilization satisfaction will be used for the final fabrication model.
